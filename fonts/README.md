# GBOT dashboard typography

`firmware/limits_font.py` contains a bitmap subset of [Inter](https://github.com/rsms/inter),
copyright 2016 The Inter Project Authors, distributed under the
[SIL Open Font License 1.1](Inter-OFL.txt). The complete font is not shipped.

Regenerate with Python and Pillow 12.3.0:

```sh
.venv/bin/python scripts/build-limits-font.py --preview /tmp/gbot-fonts.png
```

The script downloads `InterVariable.ttf` from upstream commit
`353b61b9f4430d5f420d56605a6e7993e0941470` into a temporary directory and
verifies SHA256 `4989b125924991b90d05b2d16e0e388c48f7d5bb8b30539bbf9c755278d0ccaf`.
Use `--font /path/to/InterVariable.ttf` with that same file for an offline build.
Raster output may vary with the Pillow/FreeType version; pin the host environment
for byte-identical generation.

Type is rasterized at four times its final size, downsampled with Lanczos, and
quantized to 15 nonzero coverage levels. All characters in each subset retain
the same baseline. Transparent pixels are omitted; every four bytes encode one
horizontal run `(row, x, length, alpha4)`. A space has an advance and no pixels.

| Subset | Nominal px / weight | Visible height | Run bytes |
| --- | --- | --- | --- |
| `hero` | 72 / 500 | 55 | 12,912 |
| `unit` | 26 / 400 | 21 | 1,416 |
| `brand` | 16 / 600 | 17 | 16,968 |
| `small` | 12 / 500 | 13 | 11,380 |
| `micro` | 9 / 500 | 9 | 4,620 |

Total run payload is 47,296 bytes. Font rendering uses only horizontal lines
and a 16-entry foreground/background blend palette.

## MicroPython deployment

GBOT targets MicroPython 1.29.0 (bytecode major version 6). Install the matching
host compiler from `requirements.txt` and confirm the version on your own board:

```sh
.venv/bin/pip install -r requirements.txt
./scripts/deploy.sh /dev/ttyACM0 --verify  # replace with your board port
```

Deployment first compiles all firmware modules in a temporary directory
before opening the serial port. It uploads only `limits_font.py` and
`limits.py` as `.mpy`, together with the font license. It removes
the two old `.py` files after both bytecode modules have copied successfully,
because MicroPython prefers a `.py` module over a same-named `.mpy` module.
The other modules remain Python source; `main.py` is copied last.

To rebuild the font and its bytecode without connecting a board:

```sh
.venv/bin/python scripts/build-limits-font.py --mpy-output /tmp/limits_font.mpy
```

The source compiler runs on the host, avoiding its transient memory cost on
the board. The generated bytecode size depends on the source metadata and
compiler version.
The generated file uses portable bytecode and 31-bit small integers; it does
not include native machine code. If MicroPython is upgraded, check the
[documented bytecode compatibility](https://docs.micropython.org/en/latest/reference/mpyfiles.html)
and update the pinned compiler together with the firmware.
